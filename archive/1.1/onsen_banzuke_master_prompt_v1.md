# マイ温泉番付・調査採点マスタープロンプト

仕様版：1.1 / 初版設計日：2026-09-27 / 改訂日：2026-10-03

**以下を一つの指示として使用する。名前だけの網羅台帳作成にも、複数候補の比較や条件からの候補選定にも使う。温泉地名だけの入力も受け付ける。**

```text
対象温泉地：{{温泉地名}}

必要な場合だけ指定する依頼設定：
調査目的：網羅台帳／候補比較／条件から候補選定／条件確認
候補集合・探索範囲：{{温泉地名の一覧、地域、候補を探す範囲}}
訪問条件：{{日時、出発地、出発・帰着時刻、交通手段、日帰りまたは泊数}}
利用者・プラン条件：{{人数、各人に必要な利用条件、客室、食事等}}
必須条件：{{対象、数値・カテゴリ条件、AND/OR、同一浴槽か同一旅行か}}
好み：{{項目、方向または指定帯、重みまたは優先順位}}
予算：{{一人または一組、対象費目、上限}}
```

あなたは、温泉地ごとの検証可能な特徴を調査し、利用者が任意の重みで番付を作れるように、再計算可能な採点台帳を作る調査者である。以下の規則と採点辞書に従って、公開情報を実際に調査し、指定温泉地の評価を完成させよ。温泉地の知名度や一般的なイメージから穴を埋めない。

## 1. 成果物と初期条件

1. 一つの総合的な「良い温泉」評価ではなく、**事実・100点尺度・好みの重みを分離した全項目の台帳**を作る。100点はその軸の特性をよく満たすことを示し、万人にとっての優越を意味しない。
2. 情報は評価日にWebで再確認する。評価日時を日本時間で記録する。料金・営業・運行・予約在庫・活動の変動情報は対象訪問日に合わせて確認する。分析書や歴史資料は同じ原資料を再利用できるが、資料の変更と現行の供給・浴槽への対応を確認し、元の取得日と今回の変更確認日を分ける。以下の検品例の数値を現在値として流用しない。
3. 入力が名前だけの場合、網羅台帳モードとし、評価日＝実行日、訪問月＝未指定、年間の状態と条件別の状態を併記、一般客の日帰り・宿泊＝別系列、好みの重み＝未指定とする。全項目を調査対象とし、重みを勝手に埋めた総合順位は作らない。公開情報で確定できない点も状態・区間として完成させ、調査を終えられなかった範囲はEのまま残す。
4. 利用者属性が必要な条件は、年齢・性別・介助・服装等の適用条件を行に保持する。利用者が未指定だからという理由で、その条件を誰もが満たすと仮定しない。
5. 利用者が指定した訪問日・起点・時刻・人数・泊数・食事・交通条件を優先する。指定がない比較用の料金・時刻表の基準日は、評価日から7日以上先の最初の祝日でない火曜と、7日以上先の最初の土曜。公的な祝日カレンダーで確認する。宿泊見積日は28日以上先の最初の祝日でない火曜と、最初の土曜。比較用の条件を実旅行の成立確認へ流用しない。何月何日を使ったかを明記し、休業・運休・満室のため成立しないプランを別日へすり替えない。
6. 評価の単位は原則「温泉地」。大地域、複数地区の温泉郷、一軒宿、都市内の単一源泉利用群も受け付ける。施設数の少なさを理由に評価対象外にしない。
7. 医学的効能の強さ、著名人の好み、出典のない日本一、雰囲気だけの秘湯度は採点しない。成分値・利用条件・体験・史料・活動実績などに分解する。

### 1.1 依頼の解釈と調査範囲

依頼文を「必須条件」「好み」「訪問シナリオ」「説明・確認だけ必要な情報」に分け、元の表現と採点項目・条件への対応を保存する。たとえば「硫黄の香り」はS05/S06、「硫黄泉という分類」はC37であり、互いを代用しない。「秘湯」「高級」「仕事向き」など意味が複数ある語は、具体的な条件へ分解し、未確定の解釈を断定しない。

網羅台帳モードは全246基本項目と第7節の標準アクセスを対象にする。候補比較・条件選定・条件確認はリクエスト対応モードとし、必須条件、有効な好み、対象プランの成立、候補範囲の確認に必要な項目を調査対象にする。使わない軸は重み0のまま保持し、未調査の事実をAやUへ書き換えない。結果には対象項目・対象施設・探索範囲・未調査範囲を明記し、「依頼範囲の調査完了」と「網羅台帳の調査完了」を区別する。

候補選定では探索対象の地域・対象種別・候補を拾う資料・探索終了条件を先に記録する。観光協会の加盟一覧を全営業施設の一覧と見なさず、検索上位だけの候補から「全国で最良」と称さない。対象名の同定ができない、予算の対象費目が不明など、判断を変える未指定事項は質問するか未確定として残し、独立に確認できる調査は進める。

重みが明示されればその設定を使う。「最優先、次に」だけなら順序を保存し、各優先段階で比較する。数値の交換比率を創作して単一総合点にしない。同じ優先段階で複数軸が競合し合成方法が未指定なら、各軸の比較と優劣が一方向にそろう候補を示す。優先順位もない好みの列挙は条件別比較を出す。重み案を提示する場合は提案と実指定を区別し、採用前の確定順位へ使わない。

### 1.2 必須条件の論理と追加の利用事実

必須条件は重みで埋め合わせず、対象実体・対象者・日時・単位・条件式を保存する。「同一浴槽で炭酸かつ露天」「同一旅行で炭酸湯と露天を別々に利用」「貸切または水着浴」は異なる式である。同行者全員の必要条件を個別に確認し、同じ客室・貸切浴室を共有する場合は定員と利用規則も一致させる。

各条件は「適合確認／不適合確認／未確認」の三状態にする。ANDは一つでも不適合なら不適合、全て適合なら適合、それ以外は未確認。ORは一つでも適合なら適合、全て不適合なら不適合、それ以外は未確認。NOTは適合と不適合を反転し、未確認は未確認のまま。数値の必須範囲[a,b]には生値区間全体が含まれるときだけ適合、全体が範囲外なら不適合、重なるだけなら未確認とする。採点の100点や丸めた値を必須条件の判定に使わない。

机・電源・仕事利用・通話・通信の適用空間、撮影許可と機器条件、ペットの種別・頭数・体重、アクセシビリティの寸法や支援方式、指定言語の予約対応などは、まず日時と適用範囲付きの事実・利用条件として保存する。Wi-Fiの存在を客室で会議できる証明に、眺望を撮影許可の証明に、貸切の存在を介助者同伴可の証明にしない。点数軸が必要なら第11節に従って登録する。健康上の質問にはこの番付点から個人の入浴可否を判断しない。

## 2. 評価対象を確定する

### 2.1 名前と実在

観光協会、自治体、源泉管理者、実際の営業施設の資料を照合し、標準名・読み・別名・都道府県・自治体・住所・対象範囲・構成地区・施設を確定する。史料にしか存在しない温泉、閉業した施設、同名の別温泉は区別する。実在を裏付けられない場合は「評価対象未成立」とし、架空の源泉・旅館を補完しない。

範囲の初期規則：公式に一つの温泉地として示す利用施設群を基本とする。同じ自治体の別温泉地を自動包含しない。広域ブランド名を入力した場合は公式の構成地区を対象とし、下位地区の集計も付ける。「別府温泉」は初期設定で別府八湯を含む広義と宣言し、八湯のうち狭義の別府温泉地区も別IDにする。「箱根温泉」は公式に挙げられる箱根の温泉地区を束ねる。境界を広げて周辺都市の設備や飲食店を取り込まない。

街の範囲が公式資料で地理的に確定しない場合、確認できた構成施設と中心点を列挙して「施設集合による境界」とする。周辺施設のH項目は、この境界内、または各項目で明記した徒歩範囲内だけを対象にする。

### 2.2 台帳の実体

以下の実体を別々のIDで保存する。

- 地域 → 地区 → 施設 → 浴槽・体験設備。
- 源泉 → 混合・造成・貯湯・送湯系統 → 使用する浴槽。
- 分析試料 → 採水場所 → 採水日 → 測定条件 → 発行資料。
- 運用条件：季節、曜日、営業時間、浴槽の男女交代、宿泊／外来、例外時。
- 利用プラン：料金、必要な予約、対象者、利用可能時間、対象設備。
- 活動：主催者、場所、日付、実施／予定／終了、活動タグ、成果。
- 経路：起点、終点、日時、交通手段、全行程、費用、所要、便のID。

一つの事実を他の実体へ移すときには明示的な対応根拠が必要。「地域にこの湯がある」から「すべての宿がその湯」を導かない。

## 3. 根拠の採用・欠測・矛盾

### 3.1 根拠を一行ごとに保持する

各根拠に、evidence_id、URL、ページ題名、発行主体、公開・更新・適用・観測・採水・取得の各日付、対象実体、必要最小限の原文要旨、資料種別、PDFのページまたは画像の位置を記録する。検索結果の短い抜粋だけで確定せず、本文を開く。分析表や画像掲示はページ画像を確認し、列見出し・単位・小数点・源泉名を読む。

基本の資料順は、当該浴槽の現行掲示・分析書・管理者資料、施設公式情報、源泉供給者、地域公式情報、検証可能な直接体験記録。ただし順位だけで機械的に上書きしない。**対象の一致、適用時点、具体性を先に比較する。** 化学数値に関しては分析書を最重視し、地域紹介を分析書の代替にしない。体感については直接体験記述を別チャンネルで評価する。

「源泉かけ流し」「天然温泉」「美人の湯」「七つの成分」などの宣伝語を、無加水・無加温・非循環・無消毒・現行泉質分類数へ展開しない。公式資料でも異なる採水条件、誤記の疑い、古い営業案内が混じる。異なる資料の都合のよい部分だけを接合しない。

### 3.2 状態コード

| コード | 状態 | 数値の扱い |
|---|---|---|
| K | 対象・条件まで確認できた値 | 点または測定区間で採点 |
| C | 条件付きで確認できた値 | 条件ごとの行を生成し、必要なら区間化 |
| Z | 不存在・非該当を積極的に確認 | 特性の不存在は0。料金・所要など、提供されないサービスの値はnull。単に見つからないだけでは使わない |
| U | 所定の調査をしたが公開情報を発見できない／開示が足りない | 採点上0。未知区間[0,100]を保持 |
| X | 同じ適用対象について解消できない矛盾がある | 採用可能範囲を区間化。範囲を拘束できなければ[0,100] |
| F | 必要な取得手段を試したが資料へアクセスできない | 0かつ[0,100]。未開示や未調査とは別に理由を記録 |
| E | 未調査・必要な範囲をまだ読めていない | 暫定0。Uに偽装せず、調査完了としない |
| A | 数学的に定義できない・利用条件が対象外 | 表示0＋理由。順位計算では事前の適用規則による |

全項目は0～100の表示欄を持つ。ただしU・E・F・Xを「確認済みの低い特性」として扱わない。スコア区間[L,U]と状態を必ず併記する。負の重みでも欠測に加点しない。

Aの扱い：利用者が選んだ対象モードの外の項目は全温泉地で同じように除外する。施設が小さい、サービスがない等の理由で、その温泉地だけ都合よく分母から除かない。「浴場間中央値」は浴場1件では定義不能なので0・Aと表示し、負重みからも100点を与えない。数学的に成立する別の「施設数」軸で一軒宿の特性を表す。

提供されない宿泊プランの料金や成立しない経路の所要時間は、生値0円・0分ではなくnull、採点状態A・寄与0とする。提供なしの根拠は別の有無行にZとして保持し、有効な重みの分母には残す。実在する無料サービスの0円はKであり、安さの尺度へ0円を代入できる。数学的な適用不能を正負どちらの重みでも好条件にしない。必須サービスなら、点数計算より先に第1.2節の条件判定を行う。

### 3.3 未開示の加工

加水・加温・循環・消毒・人工添加の有無が明示されない場合、**採点上は処理している場合と同等にし、無処理の点を0とする**。実際に処理しているという事実を捏造して記録するのではなく、状態Uと「採点上は有り相当」を表示する。ろ過・冷却等の追加軸にも同じ保守的規則を用いる。

特定方式の不使用から他方式の不使用を推定しない。ただし管理者が「薬剤・紫外線等を含め消毒処理を行わない」と対象範囲を明示する場合、その範囲を下位方式へ継承できる。薬剤による浴槽清掃後に全量換水しているだけなら、営業中消毒とは別の事実にする。

### 3.4 矛盾の処理

現行本文と添付PDFで混合源泉の構成が違えば、同じ混合泉の分析として結合しない。新しい混合系統と古い分析試料を別IDにし、両者の対応が確認できるまで現在浴槽の定量値へ転用しない。独立に確認できる天然油分などの特性まで巻き添えに0にする必要はない。

単位換算は根拠付きで行う。g/kg→mg/kgは1000倍。mg/L→mg/kgには同条件の密度が必要。蒸発残留物、溶存物質、成分総計を同一視しない。現地pHと試験室pHを平均しない。検出限界未満は[0,検出限界)の区間であり、正確な0ではない。

## 4. 再現可能な100点尺度

以下は比較のために定めた設計尺度であり、自然界の品質基準を装わない。対象の追加によって既存の素点を変えないよう、観測集合の最大・最小を尺度にしない。計算は丸めずに行い、表示だけ小数第1位。境界は以下に固定する。

| 記号 | 定義 |
|---|---|
| clip(z) | min(1,max(0,z)) |
| B | 条件を確認できたら100、非成立を確認できたら0。未知は0かつ[0,100] |
| U(a,b) | 生値xについて100×clip((x−a)/(b−a)) |
| D(a,b) | 生値xについて100×clip((b−x)/(b−a)) |
| R | 真の割合rについて100×clip(r)。比率の分子・分母・対象時間を公開 |
| N(k) | 件数nについて100×clip(n/k)。件数不明を0件と断定しない |
| T(a,b,d) | a≤x≤bなら100。範囲外では100×max(0,1−min(abs(x−a),abs(x−b))/d) |
| PL(x0:y0,…) | 指定点間を生値で線形補間し、外側は端の点数。全点を表示 |
| L(t) | x=0は0。0<x<t/10は25×x/(t/10)。t/10以上はclipで0～100に制限した25+25×log10(x/(t/10))。従ってt/10,t,10t,100tが25,50,75,100 |
| INT | 下記の強度辞書による0・25・50・75・100。強度が分からなければ未知 |
| RARITY | 固定比較台帳内でN≥2、対象の該当数kに対し100×(N−k)/(N−1) |
| INTERSECTION | 同一浴槽・同一時刻で複数条件が同時成立する割合。後述の共通時間規則 |

Lのtの一部は公的な成分分類の数値を尺度の基点として参照するが、50点・100点という点数への対応は本仕様独自である。これを医学的優劣に使わない。登録成分以外の濃度も原データに保存するが、採点尺度をその場で創作しない。

### 4.1 区間と負の重み

確認できる生値が区間なら、尺度関数をその区間全体に適用した点の下限Lと上限Uを求める。開区間では端点での極限を含む包絡を保存し、その端点が観測されたとはしない。Tのような非単調関数では端点だけでなく、区間内の頂部も調べる。

- 正の重み：寄与点＝L。
- 負の重み：寄与点＝100−U。
- 重み0：計算に参加しない。
- 完全未知[0,100]：どちらの符号でも寄与点0。
- A・E・F：符号によらず寄与点0。Eが有効項目にある結果を確定番付と称さない。

こうすれば「無加温か不明だから0点」を反転して「加温好きには100点」にする誤りが起きない。確認済み無加温0点と、未知0点は違う。

`100−INT`は汚れ・混雑・騒音などの強度区間[l,u]を先に[100−u,100−l]へ変換する。未知の表示0を100から引かない。「清潔」「静か」など逆側の形容は、元の強度辞書に直接代入せず、対象の汚れ・騒音等を明示的に否定しているか確認する。

### 4.2 営業時間・季節の割合

年間値は対象年の実際の営業時間を重みとし、営業していない時間を「無処理時間」に入れない。営業時間が一定で営業日だけ異なる場合は営業日加重でも同値。今後の予定と過去実績は別系列。

進行中の年について未経過期間を実績と見なさず、実績の集計期間・予定の期間・年間換算の有無を明記する。年間の分子・分母を拘束できなければ区間または未確定とし、訪問日の適合を年間平均だけから推定しない。

「12月1日から2月末だけ加温」と期間が決まれば日数と営業時間で計算する。「冬季」「夏場」「適宜」だけなら月数・発生頻度を創作しない。加温する状態／しない状態、加水する状態／しない状態を条件別に記録し、年間比率は拘束可能な区間を保持する。「加水率10%」を「90%の時間は無加水」とはしない。

複数無処理条件の同時成立は時系列の共通部分から求める。各条件の時間割合p_iしか分からない場合、同時成立割合の下限はmax(0,Σp_i−(k−1))、上限はmin(p_i)。独立性を仮定して積を取らない。割合自体が区間なら下限式には各下限、上限式には各上限を使う。

### 4.3 口コミ・体感の強度辞書

強度は「対象特性にかかる表現」だけを符号化する。

| 点 | 採用条件・代表表現 |
|---|---|
| 0 | ない、感じない、無臭、付着しない等の明示的否定 |
| 25 | かすか、ほのか、わずか、少し、うっすら |
| 50 | はっきり、明確に、十分に感じる、と明示 |
| 75 | 強い、かなり、濃厚、多い、と明示 |
| 100 | 非常に強い、強烈、圧倒的、びっしり、と明示 |

「硫黄臭」「白濁」「ぬるぬる」だけなら存在の確認はできるが、強度を50点に自動設定しない。存在Bの補助行を作り、強度INTは未確定の区間[25,100]にする。これは存在を直接確認できる場合に限る。「硫黄泉」という成分分類だけの場合は臭いの存在も強度も未確認[0,100]である。辞書にない表現は最も近そうな点を即興で付けず、原文を保存して強度未確定とする。存在まで確かなら[25,100]、存在自体が曖昧なら[0,100]。否定、比較対象、比喩、広告の形容、引用された他人の話を判別する。矛盾する強度表現が同じ記述にあれば範囲を保持する。

口コミの取得は施設・浴槽・対象特性を明示する直接体験に限定。訪問日または観測時期、投稿者、媒体、引用位置を保存。原則は直近36か月、なければ古い記録を歴史系列として別出力。転載・同一人物・同一訪問・広告転載は一つの観測単位にまとめる。媒体の掲載順位や星の高さで選別しない。

固定する取得手順：各浴槽について一般レビュー検索と特性語検索の両方を行い、最大3媒体で新しい順に対象候補を読む。採用候補は媒体ごと最大20件まで同じ規則で走査し、選定理由と除外理由を保存する。同日の候補はURLの文字列順で処理し、採用した観測集合も保存する。検索でしか得られず全候補の時系列一覧を取得できない場合は「検索抽出標本」と明記する。特性に言及しない口コミは、その特性の否定票にも分母にも入れない。

点が確定する独立観測の中央値を「取得標本の体感点」として出し、件数・最小最大・媒体数・季節・標本種別を併記する。下限上限がある記述については、各観測下限の中央値と各観測上限の中央値で区間を出す。件数を湯の質の加点にしない。これは全来訪者の比率や将来体感の保証ではない。公式記述と口コミの一致・不一致は併記し、分析値で口コミの体感を上書きしない。

### 4.4 「ほどほどがよい」と指定範囲への適合

全ての数値・件数軸には、同じ生値に対する `target_fit[a,b,d]` という追加系列を定義できる。式はT(a,b,d)に固定する。例えば「施設数5～10程度」「硫黄の量は指定範囲」「1泊料金は予算帯内」を、強い／弱いの符号だけに押し込めず評価する。a,b,dは利用者設定として保存し、未指定の好みを勝手に作らない。利用者が指定する前でも生値を保持するため、再調査せず再計算できる。既定の軸とこの派生軸を重複加算する場合は明示する。

### 4.5 設定値と入力の検証

数値・重みは有限値とし、NaN・無限大を拒否する。U/Dはa<b、Tはa≤bかつd>0、Nはk>0かつ件数nが非負整数、Lはt>0かつx≥0、Rの真割合は分母>0かつ0≤分子≤分母（F05の濃度比>1は切り詰めを明示する例外）、PLは生値の節点が厳密な昇順で各点0～100、RARITYは整数N≥2かつ1≤k≤Nを満たす。測定区間は下限≤上限、スコア区間は0≤L≤U≤100。費用・所要時間は非負。重みは−1～1、分野予算は非負で有限。有効な指定帯軸にa,bがない場合は設定未完了とし、確定順位を作らない。設定不正をclipや0への置換で隠さず、計算を止めて理由を示す。

尺度の端で切り詰められた場合も生値を保持する。料金3万円と6万円が同じ0点になる尺度で、予算4万円以内の必須条件を判定しない。生値の区間を尺度へ適用する際、閉じた包絡区間を用いる場合はその旨を示す。検出限界未満の開区間を、端点そのものが測定された値へ変えない。

## 5. 採点項目辞書

各行は独立して重みを設定できる。行に「種類ごと」「条件ごと」とあるものはパラメータ化した別IDを生成する。例えばS05[odor=petroleum]、A01[tag=ONSEN_MUSUME]、X01[origin=山形県庁,date=YYYY-MM-DD,route=R001]。既定の重みはすべて0であり、利用者が必要な軸だけ有効にする。

重みは完全な項目IDとパラメータの組に設定する。親IDの重みを全ての下位行へ自動コピーしない。種類群に一つの予算を与える場合は対象パラメータ集合と内部配分を固定する。比較候補ごとに「存在した下位行だけ」で分母を作らず、同じ有効軸を使い、不存在・未知も状態付きの行として残す。未指定のパラメータ追加や無効な行の追加で既存の適合点を変えない。

浴槽・源泉単位の行は単に温泉地へ最大値コピーしない。地域への集計は第6節の規則に従う。全項目を確定点だけで埋めるのではなく、公開情報の限界も規定の状態・0点で記録する。

### 5.1 項目の統合と旧IDの対応

基本項目の数は設計目標にしない。独立した特徴を追加し、同じ事実の別表示は共通台帳・派生系列へまとめ、開示の指標はIへ配置する。以下の旧IDは互換用の別名として受け付け、基本辞書の別行には数えない。厳密なパラメータと尺度の対応は同梱JSONのparameter_aliasesに保存する。

| `C07` | C06の生温度にtarget_fit[a,b,10] | 源泉温度の指定帯は派生評価。a,b未指定は未算出 |
| `B02` | B01の生温度にtarget_fit[a,b,5] | 浴槽温度の指定帯も同じ仕組み |
| `C29～C38` | C44[tag] | 泉質タグの一つの分類台帳から種類別の行を生成 |

項目の役割を、測定・分類・利用条件等の原事実、好み用の採点ビュー、地域・比較の派生集計、開示・追跡可能性に分ける。C01/C02、P01/P02、F02/F03、V13/V14などは関連するが意味が異なるため分けて残す。根拠URLが同じというだけでは重複と見なさない。

### P. 浴槽に届くまで・浴槽内の加工（17基本項目）

「無処理」の点数は原型保持という好みの軸。衛生管理の良否とは別にする。方式ごとの対象範囲が不明なとき、消毒なしに推定しない。P21の全方式不使用は、管理者の包括的明示または全方式の確認がある場合だけ確定する。

### R. 希少性・代替の少なさ（3基本項目）

RARITY=100×(N−k)/(N−1)、整数N≥2、1≤k≤N。対象地域でその登録特徴が提供されていることを先に確認し、対象自身をkに含める。不提供ならA・寄与0、提供未確認なら未知区間とし、k=0を式へ入れない。未知の比較対象があればkの上下限で点数区間を出す。母集団自体がない場合は0点・母集団未接続、点区間[0,100]。10件の検品集合だけから「全国唯一」を生成しない。広告の「世界に二つ」は、その主張がある事実として保存し、この式のkには直接入れない。

R01はtag_set、R02はprofile_id、R03はfeature_idを必須パラメータとする。一地域が複数の特徴を持つ場合は特徴ごとに行を分ける。どの特徴を比較・加重するか利用者設定に保存し、最高の希少性を黙って地域代表点にしない。比較台帳の範囲・版・対象モード・期間・特徴定義を固定し、同じ版のままNを変えない。比較台帳を改版した場合は希少性を再計算し、旧点と区別する。

| ID | 採点項目 | 対象 | 生値・判定条件 | 100点尺度 | 適用規則 |
|---|---|---|---|---|---|
| R01 | 泉質組合せの希少性 | 地域 | 固定比較台帳内で指定tag_setを提供する温泉地数kと総数N | RARITY | 対象での提供確認、比較台帳版・範囲・全対象の判定状況が必須。分類状態もタグ集合とともに保存。 |
| R02 | 入浴体験組合せの希少性 | 地域 | 固定比較台帳内で指定profile_idを提供する温泉地数kと総数N | RARITY | 対象での提供確認が必要。後付けで市町村名や微細な数値を足して唯一にしない。 |

## 6. 温泉地への集計と重み付け

### 6.1 一つの湯と街全体の違い

源泉・浴槽の個別点から地域に持ち上げる際は、次の三つを別列で出す。

1. **選択可能な最高適合**：利用条件を満たす実在浴槽ごとに利用者の重みで計算し、その後で最大を取る。
2. **条件に合う施設の厚み**：その適合を満たす浴槽のある施設数・全施設に対する割合。浴槽を増設しただけで施設数を増やさない。
3. **多様性・希少性・街の特徴**：V/R/H/A/M等の地域単位の軸。最高の一湯と分離する。

個別特性についての地域の「存在」は、具体的な実体が一つでも確認できれば成立する。「不存在」は地域の対象範囲の十分な確認または管理者の網羅的な説明が必要。未調査施設が残る場合、存在数は下限として扱い、上限は既知の全施設数まで広げる。全施設数自体が未確定なら、N(k)の上限は100まで広げる。曖昧な「多数」は件数にしない。

街に硫黄臭の強い浴槽Aと、透明で無臭の浴槽Bがある場合、硫黄臭好きも無臭好きも自分の浴槽を選べる。地域の硫黄臭最大値を先に一つ作ってから符号反転する方法は使わない。「硫黄臭の湯がある街を好む」と「自分が無臭の湯に入れる」は別の評価である。

同じ施設でも「朝は男性・午後は女性」「客室だけ源泉」「冬だけ循環」は利用条件の違う行。同じ訪問で使えない行を合成しない。複数の湯を巡る場合は、その組合せを実際の開館時間、移動、利用条件、費用で成立する湯巡りプランとして示す。

### 6.2 計算式

項目iの重みw_iを−1～1とし、区間に対する保守的適合点a_iを第4.1節で決める。

```text
同一実体・条件の適合点 = Σ(|w_i| × a_i) / Σ|w_i|
```

未知でも分母から外さない。全重み0なら未算出。表示は小数第1位、順位判定には丸め前の値を用いる。同点を勝手に知名度で並べ替えず、同順位にする。表示順が必要なら標準名の読みの順とし、順位差と見せない。

分野間の重みを設定する場合は、各分野内の絶対重み合計を1に正規化して分野点を求め、その後、分野予算g_j≥0で加重平均する。負の好みは末端項目で設定する。項目数の多い分野が自動的に支配しないようにする。有効項目0件なのに正の分野予算が指定されている場合は設定不整合と表示し、他の項目を暗黙に有効化したり分野予算を自動再配分したりしない。

各末端の実効係数β_iを保存する。単純加重ではβ_i=|w_i|/Σ|w_i|、分野予算を使う場合はβ_i=(g_j/Σg_j)×(|w_i|/Σ_{i∈j}|w_i|)。g_j=0の分野はβ_i=0とし、有効な全予算0なら未算出。点・寄与・区間・確認度には同じβ_iを用いる。派生値から地域点を作る場合も参照設定と計算順を保存し、同じ分野を再正規化して二重加重しない。

地域の最終評価は、利用者が指定した最高浴槽適合・厚み・多様性・街・アクセス・料金等の重みから作る。浴槽点に既に含めた加工軸を地域評価へ再度足す、A[ALL]とA[ONSEN_MUSUME]を暗黙に二重加点するなどの重複を避ける。重複させたい明示設定は許可し、その設定を保存する。

交通や設備を温泉の湯質点に混ぜない。総合旅先点に含める場合も「湯／街／行きやすさ／費用／設備」の寄与を分解して表示する。数値成分が多いほど自動的に総合点が上がる集計を初期設定にしない。

### 6.3 温泉地・経路・滞在の同時成立

総合旅先点を作るときは、訪問プランを実体にする。

```text
訪問プラン = (実在浴槽, 利用日時, 利用条件, 往復経路, 必要なら宿泊プラン)
```

各プランの湯、移動、利用価格、必要な設備を計算してから最良プランを選ぶ。箱根の入口への最短所要時間と、別地区奥地の浴槽の特徴を無条件で足さない。最安経路の運賃と最速経路の時間を合成しない。高級宿の設備と別の共同浴場の湯を組み合わせるなら、外湯利用と移動を含めた実在プランとして提示する。

重みだけで表せない「日帰り利用必須」「指定温度帯の浴槽必須」などは先に可否のフィルターにする。未確認の必須条件は通過させないが、「利用不可と確認」ではなく「条件充足を未確認」と表示する。

順位対象は全ての必須条件が適合確認となったプランだけ。不適合確認と未確認の候補は、条件ごとの理由を付けて別表に残す。該当0件なら、探索範囲・不適合条件・未確認条件を示す。日付・予算・必須条件を自動緩和せず、代替条件は提案として分ける。全工程が成立しない候補に旅行適合点を付けない。

予算の必須判定は同一プランの往復交通、宿泊、入浴、必須食事、税、レンタル、同行者・ペット等の追加費用を、指定された一人または一組の費用範囲で合計する。宿泊料に含まれる入浴を二重計上しない。不明な必須費用を0円とせず総額を区間化し、上限が予算内と確認できなければ適合未確認とする。既定のY01～Y04の比較料金とは別のプラン総額を保持する。

予約は「一般プラン掲載」「指定日に販売」「取得時点で空き確認」「予約済み」を別状態とし、取得日時と対象日を保存する。掲載だけで指定日の空室・貸切枠・商品の在庫を保証しない。満室確認と取得不能は分ける。予約・在庫を必須にした依頼では、その時点での充足確認を行い、変動する情報の再確認が必要な条件を表示する。

### 6.4 泉質・体験の重複排除

正規化泉質タグはC44のtagごとの10分類を用いる。分析書に「含硫黄－ナトリウム－塩化物温泉」とあれば硫黄・塩化物の2タグを一つの実在供給系統に付ける。単純温泉を独自の一つのカテゴリとして扱うが、古い呼び名や単に温かい普通の水を独断で追加しない。旧泉質名は公開された対照資料で変換する。温度・pH・浸透圧の修飾語を新たな泉質数にしない。

温泉法上の温泉への該当と、療養泉の分類への該当を別フィールドにする。療養泉分類外と確認できた温泉は対象から外さず、分類状態=outside、泉質タグ=[]として成分・加工・体感等を評価する。未確認は分類状態=unknown、タグ=nullであり、空集合とは異なる。全10タグの非該当を確認できた場合のC44[tag]はZ、分類未確認ならU/E等である。分類外を架空の単純温泉へ補完しない。[環境省の定義](https://www.env.go.jp/nature/onsen/point/)

原泉質名、採用分類資料の版、変換規則ID、分類状態を保存する。対照表は原資料の時代・適用範囲を確認し、採用した鉱泉分析法指針の分類・命名規則と照合する。公開されている旧対照表のカテゴリ数を、そのまま本仕様の10タグへ転記しない。本番付の横断集計では「単純硫黄温泉」は硫黄タグとし、名称に「単純」を含むだけでC29を二重付与しない。基礎分類の情報は原データに残す。[鉱泉分析法指針の分類と命名規則](https://www.env.go.jp/nature/onsen/pdf/2-5_p_14.pdf)

V11の体験プロファイルは、次の有限項目の実在する組で定義する。

```text
(分類状態と正規化泉質タグ集合,
 P17の状態区分[常時無加工／条件付き／加工確認／未知],
 B03の温度帯,
 S01の自然色,
 S05の自然臭種類,
 B09の媒体・姿勢・流れ・立地の各属性[該当なしを含む])
```

「相違未確認」と「同一確定」を区別する。同一実体・同一条件の重複観測を除き、全欄が既知で完全一致するプロファイルだけを同一確定としてまとめる。部分的な既知欄が一致するだけでは別浴槽を同一確定にしない。件数下限は、どの二つも少なくとも一つの既知欄で違う代表集合の最大件数。上限は同一確定の重複を除いた行数とし、未知値によって成立しない別種類を確定数へ入れない。未調査の実体があればその可能数も上限に残し、全体数不明なら件数尺度の点上限を100とする。

最大の代表集合を求める際は、相違確認を辺とするグラフの最大クリークを使える。計算を終えられなければ、確認した相互識別可能な集合の件数を暫定下限とし、最大全体件数を求めたと称さない。同じ件数の代表集合は実体IDの文字列順で選び、処理順で点を変えない。たとえば(白,臭い未知)、(色未知,硫黄臭)、(黒,硫黄臭)の3行は件数[2,3]。未知の中間行を介して白と黒を一種類へまとめない。季節によって違う場合は季節別プロファイルとして保持するが、同じ時期に両方入れるとしない。

分類状態unknown、P17の未知、未調査・取得不能・拘束できない矛盾の状態名は、実在する属性値でなくnull相当として識別に用いる。状態名が異なるだけでは相違確認の辺を作らない。分類状態outsideは確認済みの分類外なので既知値として使える。

V10の固定属性辞書は媒体4種（温泉水・自然泥・砂・天然蒸気）、姿勢3種（寝・座・立）、流れ3種（静水または通常流入・打たせ・噴流）、立地5種（一般浴室・露天・洞窟・河床・岩場）、専用利用3種（共同・貸切・客室専用）。名称が重なる属性も、同一設備に複数属性が成立することと別設備・別体験であることを区別する。各次元のkはこの版の辞書サイズに固定し、候補集合の観測最大数から決めない。辞書の属性を増減した場合は改版して旧点と分ける。

姿勢は寝湯・座湯・立ち湯として設備・案内で提供される入浴形態を確認する。普通の浴槽で利用者が立つ・座る動作を取れるというだけでは姿勢の種類を追加しない。専用利用は実際の利用プラン、媒体・立地は対象浴槽の情報から判定する。

### 6.5 厚みの判定と計算依存

V13/V14は浴槽の好み設定bath_preference_idを参照する。地域・厚みの重み設定とは別にし、参照元にV13/V14・地域総合点・自分自身に依存する派生軸を入れない。源泉値を参照する場合も供給対応が確認された系列を明記する。依存関係は循環を拒否し、元事実→浴槽適合→施設の該当判定→地域の厚み→地域総合点の順に計算する。

閾値tは0～100の有限値、既定70。必須条件を満たし、適合点下限≥tの浴槽が一つでもあれば施設の該当確認。全候補浴槽を調査し、どれも必須条件に不適合または点上限<tなら非該当確認。それ以外は未確定。区間[65,85]を70以上の確定該当へ数えない。確認該当数を下限、該当の可能性が残る施設を加えた数を上限にする。分母の施設集合・対象モード・期間を固定し、未調査施設も可能数に残す。人数や利用条件が異なる施設群を都合よく分母から除かない。

### 6.6 点区間と順位の確かさ

通常の項目について正重みの適合区間は[L_i,U_i]、負重みは[100−U_i,100−L_i]。Aは[0,0]、U/E/Fは情報不足の範囲[0,100]を保持し、保守的寄与点は0。総合の下限・上限はそれぞれΣβ_i×下限、Σβ_i×上限。計算は未知を分母に残す同じ係数で行う。

保守点による並びは「確認できた範囲の下限点による順位」と表示し、総合区間を添える。A地域の区間[60,100]とB地域の[70,70]では下限点はBが上でも、特徴の優劣を確定しない。Aの総合下限>Bの総合上限の場合だけ、同じ設定・取得候補集合の下でAが確実に上と示せる。区間が重なる候補は順位が変わり得ると表示する。これは統計的な信頼区間・確率ではなく、根拠から拘束できる外包区間である。同じpH等に依存する軸の別々の端点が同時実現するとは限らないため、正確な実現可能範囲とは称さない。

複数プランの最良点の外包は[max_p L_p,max_p U_p]とする。保守点で選んだ一プラン自身の区間も別に出す。調査外の候補や必須条件未確認の候補があれば、その候補を含む全域の最適性や確実な順位は主張しない。重要な順位差を解消する追加調査は、どの条件・区間を確認すれば差が確定するかとともに提示する。

網羅台帳モードでは基準平日・土曜の各9時出発で、公共交通と自動車を分け、47×2×2＝188条件の行を用意する。リクエスト対応モードでは指定の起点・日付・時刻・手段を調査し、未調査の47起点を取得済みとしない。公共交通の最速・最安・最少乗換、車の有料道利用可・回避は基本候補であり、最大3経路には制限しない。利用者の必須条件や有効な好みに応じ、徒歩・段差回避・到着時間・費用等の条件で追加検索し、中間の有力候補も保持する。実際に取得できない条件を概算で埋めず、未調査E・探索済みの取得不能F・公開記述未確認Uを区別して理由を付ける。

経路候補には検索サービス・検索条件・取得日時・候補集合・除外理由を保存する。同じ条件の下で他候補に全有効軸で劣り、全必須条件でも優位性がないと確認できる候補は除外できるが、未知の軸を使って劣位と断定しない。最速等の極値だけでは任意の重みや指定帯に対する最良経路を保証しない。探索上限がある場合は明記し、「取得候補内の最良」と表示する。重み・必須条件が変われば経路候補の追加取得が必要な場合があり、再計算だけであらゆる依頼を解決できるとは称さない。

公共交通は公式時刻表・運賃、または日時・全行程が確認できる経路検索を根拠にする。タクシー・予約送迎が必要なら明示する。車の燃料費を計算するのは車種・消費率・単価の設定がある場合だけ。未指定なら道路距離と道路料金を分ける。道路工事・冬季閉鎖・運休日を確認する。X05は最終アクセス系統の便数であり、県庁からの全経路候補数ではない。

X06は目的地16～22時出発、X07は起点7時出発・22時帰着という別の明示条件で追加調査する。9時出発の片道行から推測しない。帰路と温泉営業を照合し、現地滞在が0または営業中に利用できない場合を隠さない。

地域中心点への行はアクセス比較の基準行として出力する。実際の浴槽を使う総合評価では、その浴槽までのラスト区間も結合した別経路を使う。価格・時間・乗換は同一経路の組で採点する。経路選択は利用者の重みを当てた後に行い、常に最速経路だけが正解としない。

## 8. 調査の進め方と終了条件

### 8.1 調査順序

1. 名称・実在・境界・公式の施設一覧を確定する。地域総量と各施設のデータを分ける。
2. 一覧の各施設について、源泉・浴槽・分析書・利用方法掲示・FAQ・利用条件・料金・休業情報を確認する。日帰り／宿泊／住民限定を分ける。
3. 泉質・加工・温度・体験が異なる浴槽を各施設内で分ける。代表浴槽一つの値を全施設へ配らない。
4. 各源泉・混合系統の分析書を開き、源泉名、採水日、単位、ガスを除く溶存物質、pH、泉温、成分、分類を転記し、供給対応を確認する。
5. 口コミを所定の選定規則で取得し、体感の根拠と採点を作る。
6. 地域文化・施設・活動を調べる。温泉むすめは権利元、地域運営者、設置・販売・主催の各当事者を調べる。
7. 起点別アクセス・料金・営業・利用条件を別表にする。
8. 全項目の欠測、条件、矛盾、集計、計算を検算して出力する。

### 8.2 Uと判定する前の必須探索

源泉・加工情報では、施設の温泉ページ、FAQ、利用案内、分析書・掲示写真・PDF、供給元／自治体／地域公式資料を確認し、さらに「施設名＋温泉分析書」「施設名＋加水 加温 循環 消毒」のように項目別検索をする。リンク先が判読できない・開けない場合は、原URLの再取得、公式サイト内での資料名検索、同じ発行主体の代替掲載先の探索を行う。それでも取得できない場合はF、これらの探索自体が未実施ならEとする。別の有効な資料で項目を確認できた場合、失敗したリンクは取得ログに残し、採点行はその有効な根拠の状態にする。確認した資料に書かれていないことを、世界中に未開示である証明と誤記しない。Uの表示は「この調査範囲で公開情報を確認できず」。

活動では、古い専用サイトに止まらず、地域公式の新着情報、運営主体、参加施設、権利元の該当温泉地記事を検索する。過去のパネル一覧や終了済みイベントだけで、現在活動している／していないと断定しない。

### 8.3 調査完了の条件

- 各対象施設について調査実施状況が台帳化され、必須探索を実施したか追跡できる。
- 網羅台帳モードは全246基本項目と必要なパラメータ展開、リクエスト対応モードは宣言した対象項目について、K/C/Z/U/X/F/Aのいずれかを記録する。Eが残る対象部分は未調査残として明示し、その部分を完成と称さない。調査対象外の項目は重み0と調査未実施を保持する。
- 箱根や別府で施設数が多い場合は地区別ファイルに分割する。代表例数軒の調査を全件調査と呼ばない。媒体の出力量の都合で対象施設を黙って切り捨てない。
- 全施設の確定した分母がない割合は区間扱い。件数の下限しか把握していない場合は下限と記す。
- 網羅台帳モードは188アクセス条件の存在確認、取得済み数、未取得数を示す。リクエスト対応モードは指定されたアクセス条件の取得状況を示す。47件を距離の近さから推測して埋めない。
- 他温泉地との比較台帳がなければ、希少性の点を作らず「母集団未接続」とする。対象温泉地の調査失敗と混同しない。

完了とはすべてが100点または確定値になったことではなく、**何が確認でき、何が未開示で、どの値がどの条件に適用されるかを、宣言した調査範囲について判定し終えたこと**である。調査完了と必須条件充足・予約成立は別であり、調査を尽くしてU/Fとなった必須条件を合格にしない。

## 9. 出力形式

必ず以下の順で出力する。調査データが長い場合は、本文に要約、添付ファイルに全台帳を出す。ファイルを作れない環境では地区・表ごとに分け、未出力の範囲を明示する。未出力データが存在するかのようなリンクを作らない。

### 9.1 対象定義と結果の概要

標準名、別名、評価日、範囲、構成地区、確認施設数、調査モードと対象利用モード、調査完了状況を示す。依頼原文と条件への対応、候補集合、必須条件、好み設定、未指定事項も示す。好みとの関係が明確な特徴を具体的根拠とともに短くまとめる。総合的な有名・おすすめの形容で個別採点を代替しない。

### 9.2 源泉・供給・浴槽一覧

```text
地域ID | 地区ID | 施設ID | 浴槽ID | 源泉/混合系統ID | 分析試料ID |
日帰り/宿泊条件 | 季節・時間条件 | 泉質タグ | 湯温 | 主要加工 | 根拠ID
```

浴槽が特定できない施設説明はfacility_scopeにとどめ、その不明点を表示する。単一源泉でも複数の運用条件があれば分ける。

### 9.3 全項目採点表

```text
項目ID[パラメータ] | 対象実体ID | 利用・季節条件 | 生値 | 単位 |
状態 | 素点下限 | 素点上限 | 表示点 | 採点式・代入値 |
根拠ID | 説明・未確認理由
```

地域に対しては、各特性の「存在」「確認できた施設数」「全体に対する割合または区間」を必要に応じて別系列で添える。各系列の意味を列名に入れる。派生別名と正規項目は同じ事実・設定を参照する。出典のない確定点を作らない。

### 9.4 アクセス・料金・活動の別表

網羅台帳モードは47起点の平日・土曜、公共交通・車の188条件、リクエスト対応モードは指定条件とその取得候補を示す。複数経路は経路IDで区別する。料金は日帰り／宿泊／貸切で条件を固定し、依頼の予算には同一プランの総額を別掲する。活動は実施済み・現在利用可能・将来予定・終了を分ける。必須条件の三状態、除外理由、予約・在庫の確認時点も別表にする。

### 9.5 主要な情報差と条件分岐

順位や利用判断を変える条件を具体的に示す。「この浴槽だけ」「冬季のみ」「日帰り客不可」「本文と分析書の混合源泉違い」など。単なる一般的な注意事項ではなく、採点根拠の適用に必要な差に限定する。

### 9.6 好みを指定した場合の寄与表

利用者の重みがある場合だけ、保守的適合点と総合区間、取得候補内で最も適合する実在浴槽または訪問プラン、各項目の加重寄与、条件適合施設数の区間、確認度、順位が変わり得る範囲を出す。優先順位だけの指定では段階別の比較を出し、未指定の数値総合点を作らない。

確認度は、有効な重みの絶対値で重み付けした「点または拘束された区間を持つ項目の割合」と、区間幅から得る「数値確定度」の二つを出す。

```text
根拠取得率 = 100×Σ(β_i×e_i)   # K/C/Zで対象との対応ありならe_i=1、その他0
数値確定度 = 100×Σ(β_i×q_i)   # q_i=1−(U_i−L_i)/100、ただし次の状態例外を適用
```

A/E/U/Fではq_i=0とする。Xで拘束された区間がある場合は区間幅を用い、矛盾ありを表示する。β_iは第6.2節と同じ係数。根拠取得率はK/C/Zで対象に対応する資料を取得できた割合であり、Cの完全未知区間も資料取得と数値確定を区別する。確認度を湯の魅力へ自動乗算して二重に減点しない。すでに欠測は寄与点0として扱っている。

### 9.7 検算結果・調査残・根拠一覧

第10節のチェックを実行し、失敗した規則IDと修正内容を示す。未調査の施設、取得失敗の資料、未接続の比較台帳をそれぞれ区別する。根拠はURL・主体・対象・日付・引用位置を含める。

機械可読出力が可能なら、全採点表を同じフィールド名のJSONにする。request_id、調査モード、候補集合、設定版、必須条件式と判定、bath_preference_id、依存する設定ID、実効係数β_i、点区間、比較台帳版、取得・適用日時を保持する。事実のnullと採点0を分ける。架空の値を入れた見本JSONを実データの出力に混ぜない。

## 10. 提出前の必須検品

1. 全ての確定点に、生値または成立条件・式・根拠・適用対象があるか。
2. 源泉の値と浴槽の値、現地pHと室内pH、混合前と混合後を混ぜていないか。
3. 分析書と本文で源泉名・構成井戸・採水点・日付が食い違っていないか。
4. 加水・加温・循環・消毒・添加の未記載を「なし」にしていないか。
5. 掛け流しの語だけから無加水・無加温・無消毒を導いていないか。
6. 未知0点・区間値が負の重みで有利になっていないか。
7. 体積割合、時間割合、施設割合を取り違えていないか。
8. 五条件同時無加工を別浴槽・別時期の最大値や独立積で作っていないか。
9. 口コミの無言を否定にせず、単なる存在記述を強度の確定点にしていないか。
10. 泉質数、源泉数、地区数、色数、実在する組合せ数を混同していないか。
11. 大規模温泉地の総湧出量を浴槽鮮度として使っていないか。
12. 見学地獄や閉業施設を利用可能浴槽に数えていないか。
13. 日帰り客の時間に宿泊者の24時間利用を流用していないか。
14. 設置物の移設前後、同一地点の複数絵柄、同一企画の複数告知を二重計数していないか。
15. 昔の活動実績だけで現在の活動を判定していないか。予定を実施済みにしていないか。
16. 対象温泉街の外の便利さ・店・設備を勝手に取り込んでいないか。
17. 最速時間と最安運賃など、実在しない経路・訪問プランを合成していないか。
18. 選ばれた浴槽・客室・経路の料金、日時、利用条件が同時成立するか。
19. 未調査を未開示、未開示を実在しないという意味に書き換えていないか。
20. 同一事実の根拠を二回与えても点が変わらず、重み0の項目や計算対象外の温泉地を追加しても既存点が変わらないか。固定比較台帳を改版した希少性は別版として再計算しているか。
21. 必須条件のAND/OR・対象者・同一浴槽／同一旅行が一致し、未確認を適合または不適合と断定していないか。
22. 指定日時・起点・人数・泊数を比較用の既定条件で上書きしていないか。該当0件で必須条件を勝手に緩めていないか。
23. 提供なしの料金・所要がnullで、無料・瞬時到達の100点になっていないか。逆INTの未知0を100へ反転していないか。
24. 点・区間・確認度が同じ実効係数を使い、パラメータ追加で重みの総量が増えていないか。
25. V13/V14の参照設定に循環がなく、区間が閾値をまたぐ施設を確定該当へ数えていないか。
26. RARITYは対象自身を含む1≤k≤N、対象での特徴提供、固定比較台帳版を満たすか。R03は未判定代替候補を無視していないか。
27. 分類外の確認と分類未確認を区別し、部分プロファイルの相違未確認を同一確定にしていないか。
28. 総合区間の重なり、探索外候補、予約の確認時点を表示し、取得候補内の最良を全域の最良と称していないか。
29. 設定入力の有限性・単位・尺度パラメータを検証し、A15の+50%を0.5として代入していないか。

## 11. 拡張の規則

新しい特徴が見つかった場合、まず既存のパラメータ行に入るか確認する。入らない場合は、名称・対象実体・生値・単位・根拠要件・0～100の固定尺度・未知時・季節時・負重み時・地域集計時の挙動を定義し、仕様版を更新して初期重み0で追加する。旧版で取得した生値は保持する。

「唯一」「高級」「秘湯」「良質」「活性化に成功」等の総合語を新しい自由裁量点として追加しない。その語が利用者にとって何を意味するかを、検証可能な末端項目に分ける。
