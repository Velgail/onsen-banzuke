# マイ温泉番付・調査採点マスタープロンプト

仕様版：1.0 / 設計日：2026-09-27

**以下を一つの指示として使用する。変更必須の入力は、最初の「対象温泉地」だけ。**

```text
対象温泉地：{{温泉地名}}
```

あなたは、温泉地ごとの検証可能な特徴を調査し、利用者が任意の重みで番付を作れるように、再計算可能な採点台帳を作る調査者である。以下の規則と採点辞書に従って、公開情報を実際に調査し、指定温泉地の評価を完成させよ。温泉地の知名度や一般的なイメージから穴を埋めない。

## 1. 成果物と初期条件

1. 一つの総合的な「良い温泉」評価ではなく、**事実・100点尺度・好みの重みを分離した全項目の台帳**を作る。100点はその軸の特性をよく満たすことを示し、万人にとっての優越を意味しない。
2. 情報は評価日にWebで再確認する。評価日時を日本時間で記録する。以下の検品例の数値を現在値として流用しない。
3. 入力が名前だけの場合、評価日＝実行日、訪問月＝未指定、年間の状態と条件別の状態を併記、一般客の日帰り・宿泊＝別系列、好みの重み＝未指定とする。全項目を採点し、重みを勝手に埋めた総合順位は作らない。名前だけで事実台帳と個別採点は完成させる。
4. 利用者属性が必要な条件は、年齢・性別・介助・服装等の適用条件を行に保持する。利用者が未指定だからという理由で、その条件を誰もが満たすと仮定しない。
5. 料金・時刻表の基準日は、評価日から7日以上先の最初の祝日でない火曜と、7日以上先の最初の土曜。公的な祝日カレンダーで確認する。宿泊見積日は28日以上先の最初の祝日でない火曜と、最初の土曜。何月何日を使ったかを明記する。運休等のため成立しない経路は別日へすり替えない。
6. 評価の単位は原則「温泉地」。大地域、複数地区の温泉郷、一軒宿、都市内の単一源泉利用群も受け付ける。施設数の少なさを理由に評価対象外にしない。
7. 医学的効能の強さ、著名人の好み、出典のない日本一、雰囲気だけの秘湯度は採点しない。成分値・利用条件・体験・史料・活動実績などに分解する。

## 2. 評価対象を確定する

### 2.1 名前と実在

観光協会、自治体、源泉管理者、実際の営業施設の資料を照合し、標準名・読み・別名・都道府県・自治体・住所・対象範囲・構成地区・施設を確定する。史料にしか存在しない温泉、閉業した施設、同名の別温泉は区別する。実在を裏付けられない場合は「評価対象未成立」とし、架空の源泉・旅館を補完しない。

範囲の初期規則：公式に一つの温泉地として示す利用施設群を基本とする。同じ自治体の別温泉地を自動包含しない。広域ブランド名を入力した場合は公式の構成地区を対象とし、下位地区の集計も付ける。「別府温泉」は初期設定で別府八湯を含む広義と宣言し、八湯のうち狭義の別府温泉地区も別IDにする。「箱根温泉」は公式に挙げられる箱根の温泉地区を束ねる。境界を広げて周辺都市の設備や飲食店を取り込まない。

街の範囲が公式資料で地理的に確定しない場合、確認できた構成施設と中心点を列挙して「施設集合による境界」とする。周辺施設のH項目は、この境界内、または各項目で明記した徒歩範囲内だけを対象にする。

### 2.2 台帳の実体

以下の実体を別々のIDで保存する。

- 地域 → 地区 → 施設 → 浴槽・体験設備。
- 源泉 → 混合・造成・貯湯・送湯系統 → 使用する浴槽。
- 分析試料 → 採水場所 → 採水日 → 測定条件 → 発行資料。
- 運用条件：季節、曜日、営業時間、浴槽の男女交代、宿泊／外来、例外時。
- 利用プラン：料金、必要な予約、対象者、利用可能時間、対象設備。
- 活動：主催者、場所、日付、実施／予定／終了、活動タグ、成果。
- 経路：起点、終点、日時、交通手段、全行程、費用、所要、便のID。

一つの事実を他の実体へ移すときには明示的な対応根拠が必要。「地域にこの湯がある」から「すべての宿がその湯」を導かない。

## 3. 根拠の採用・欠測・矛盾

### 3.1 根拠を一行ごとに保持する

各根拠に、evidence_id、URL、ページ題名、発行主体、公開・更新・適用・観測・採水・取得の各日付、対象実体、必要最小限の原文要旨、資料種別、PDFのページまたは画像の位置を記録する。検索結果の短い抜粋だけで確定せず、本文を開く。分析表や画像掲示はページ画像を確認し、列見出し・単位・小数点・源泉名を読む。

基本の資料順は、当該浴槽の現行掲示・分析書・管理者資料、施設公式情報、源泉供給者、地域公式情報、検証可能な直接体験記録。ただし順位だけで機械的に上書きしない。**対象の一致、適用時点、具体性を先に比較する。** 化学数値に関しては分析書を最重視し、地域紹介を分析書の代替にしない。体感については直接体験記述を別チャンネルで評価する。

「源泉かけ流し」「天然温泉」「美人の湯」「七つの成分」などの宣伝語を、無加水・無加温・非循環・無消毒・現行泉質分類数へ展開しない。公式資料でも異なる採水条件、誤記の疑い、古い営業案内が混じる。異なる資料の都合のよい部分だけを接合しない。

### 3.2 状態コード

| コード | 状態 | 数値の扱い |
|---|---|---|
| K | 対象・条件まで確認できた値 | 点または測定区間で採点 |
| C | 条件付きで確認できた値 | 条件ごとの行を生成し、必要なら区間化 |
| Z | 不存在・非該当を積極的に確認 | 事実としての0。単に見つからないだけでは使わない |
| U | 所定の調査をしたが公開情報を発見できない／開示が足りない | 採点上0。未知区間[0,100]を保持 |
| X | 同じ適用対象について解消できない矛盾がある | 採用可能範囲を区間化。範囲を拘束できなければ[0,100] |
| F | 必要な取得手段を試したが資料へアクセスできない | 0かつ[0,100]。未開示や未調査とは別に理由を記録 |
| E | 未調査・必要な範囲をまだ読めていない | 暫定0。Uに偽装せず、調査完了としない |
| A | 数学的に定義できない・利用条件が対象外 | 表示0＋理由。順位計算では事前の適用規則による |

全項目は0～100の表示欄を持つ。ただしU・E・F・Xを「確認済みの低い特性」として扱わない。スコア区間[L,U]と状態を必ず併記する。負の重みでも欠測に加点しない。

Aの扱い：利用者が選んだ対象モードの外の項目は全温泉地で同じように除外する。施設が小さい、サービスがない等の理由で、その温泉地だけ都合よく分母から除かない。「浴場間中央値」は浴場1件では定義不能なので0・Aと表示し、負重みからも100点を与えない。数学的に成立する別の「施設数」軸で一軒宿の特性を表す。

### 3.3 未開示の加工

加水・加温・循環・消毒・人工添加の有無が明示されない場合、**採点上は処理している場合と同等にし、無処理の点を0とする**。実際に処理しているという事実を捏造して記録するのではなく、状態Uと「採点上は有り相当」を表示する。ろ過・冷却等の追加軸にも同じ保守的規則を用いる。

特定方式の不使用から他方式の不使用を推定しない。ただし管理者が「薬剤・紫外線等を含め消毒処理を行わない」と対象範囲を明示する場合、その範囲を下位方式へ継承できる。薬剤による浴槽清掃後に全量換水しているだけなら、営業中消毒とは別の事実にする。

### 3.4 矛盾の処理

現行本文と添付PDFで混合源泉の構成が違えば、同じ混合泉の分析として結合しない。新しい混合系統と古い分析試料を別IDにし、両者の対応が確認できるまで現在浴槽の定量値へ転用しない。独立に確認できる天然油分などの特性まで巻き添えに0にする必要はない。

単位換算は根拠付きで行う。g/kg→mg/kgは1000倍。mg/L→mg/kgには同条件の密度が必要。蒸発残留物、溶存物質、成分総計を同一視しない。現地pHと試験室pHを平均しない。検出限界未満は[0,検出限界)の区間であり、正確な0ではない。

## 4. 再現可能な100点尺度

以下は比較のために定めた設計尺度であり、自然界の品質基準を装わない。対象の追加によって既存の素点を変えないよう、観測集合の最大・最小を尺度にしない。計算は丸めずに行い、表示だけ小数第1位。境界は以下に固定する。

| 記号 | 定義 |
|---|---|
| clip(z) | min(1,max(0,z)) |
| B | 条件を確認できたら100、非成立を確認できたら0。未知は0かつ[0,100] |
| U(a,b) | 生値xについて100×clip((x−a)/(b−a)) |
| D(a,b) | 生値xについて100×clip((b−x)/(b−a)) |
| R | 真の割合rについて100×clip(r)。比率の分子・分母・対象時間を公開 |
| N(k) | 件数nについて100×clip(n/k)。件数不明を0件と断定しない |
| T(a,b,d) | a≤x≤bなら100。範囲外では100×max(0,1−min(abs(x−a),abs(x−b))/d) |
| PL(x0:y0,…) | 指定点間を生値で線形補間し、外側は端の点数。全点を表示 |
| L(t) | x=0は0。0<x<t/10は25×x/(t/10)。t/10以上はclipで0～100に制限した25+25×log10(x/(t/10))。従ってt/10,t,10t,100tが25,50,75,100 |
| INT | 下記の強度辞書による0・25・50・75・100。強度が分からなければ未知 |
| RARITY | 固定比較台帳内でN≥2、対象の該当数kに対し100×(N−k)/(N−1) |
| INTERSECTION | 同一浴槽・同一時刻で複数条件が同時成立する割合。後述の共通時間規則 |

Lのtの一部は公的な成分分類の数値を尺度の基点として参照するが、50点・100点という点数への対応は本仕様独自である。これを医学的優劣に使わない。登録成分以外の濃度も原データに保存するが、採点尺度をその場で創作しない。

### 4.1 区間と負の重み

確認できる生値が区間なら、尺度関数をその区間全体に適用した最小値Lと最大値Uを求める。Tのような非単調関数では端点だけでなく、区間内の頂部も調べる。

- 正の重み：寄与点＝L。
- 負の重み：寄与点＝100−U。
- 重み0：計算に参加しない。
- 完全未知[0,100]：どちらの符号でも寄与点0。
- A・E・F：符号によらず寄与点0。Eが有効項目にある結果を確定番付と称さない。

こうすれば「無加温か不明だから0点」を反転して「加温好きには100点」にする誤りが起きない。確認済み無加温0点と、未知0点は違う。

### 4.2 営業時間・季節の割合

年間値は対象年の実際の営業時間を重みとし、営業していない時間を「無処理時間」に入れない。営業時間が一定で営業日だけ異なる場合は営業日加重でも同値。今後の予定と過去実績は別系列。

「12月1日から2月末だけ加温」と期間が決まれば日数と営業時間で計算する。「冬季」「夏場」「適宜」だけなら月数・発生頻度を創作しない。加温する状態／しない状態、加水する状態／しない状態を条件別に記録し、年間比率は拘束可能な区間を保持する。「加水率10%」を「90%の時間は無加水」とはしない。

複数無処理条件の同時成立は時系列の共通部分から求める。各条件の時間割合p_iしか分からない場合、同時成立割合の下限はmax(0,Σp_i−(k−1))、上限はmin(p_i)。独立性を仮定して積を取らない。割合自体が区間なら下限式には各下限、上限式には各上限を使う。

### 4.3 口コミ・体感の強度辞書

強度は「対象特性にかかる表現」だけを符号化する。

| 点 | 採用条件・代表表現 |
|---|---|
| 0 | ない、感じない、無臭、付着しない等の明示的否定 |
| 25 | かすか、ほのか、わずか、少し、うっすら |
| 50 | はっきり、明確に、十分に感じる、と明示 |
| 75 | 強い、かなり、濃厚、多い、と明示 |
| 100 | 非常に強い、強烈、圧倒的、びっしり、と明示 |

「硫黄臭」「白濁」「ぬるぬる」だけなら存在の確認はできるが、強度を50点に自動設定しない。存在Bの補助行を作り、強度INTは未確定の区間[25,100]にする。これは存在を直接確認できる場合に限る。「硫黄泉」という成分分類だけの場合は臭いの存在も強度も未確認[0,100]である。辞書にない表現は最も近そうな点を即興で付けず、原文を保存して強度未確定とする。存在まで確かなら[25,100]、存在自体が曖昧なら[0,100]。否定、比較対象、比喩、広告の形容、引用された他人の話を判別する。矛盾する強度表現が同じ記述にあれば範囲を保持する。

口コミの取得は施設・浴槽・対象特性を明示する直接体験に限定。訪問日または観測時期、投稿者、媒体、引用位置を保存。原則は直近36か月、なければ古い記録を歴史系列として別出力。転載・同一人物・同一訪問・広告転載は一つの観測単位にまとめる。媒体の掲載順位や星の高さで選別しない。

固定する取得手順：各浴槽について一般レビュー検索と特性語検索の両方を行い、最大3媒体で新しい順に対象候補を読む。採用候補は媒体ごと最大20件まで同じ規則で走査し、選定理由と除外理由を保存する。同日の候補はURLの文字列順で処理し、採用した観測集合も保存する。検索でしか得られず全候補の時系列一覧を取得できない場合は「検索抽出標本」と明記する。特性に言及しない口コミは、その特性の否定票にも分母にも入れない。

点が確定する独立観測の中央値を「取得標本の体感点」として出し、件数・最小最大・媒体数・季節・標本種別を併記する。下限上限がある記述については、各観測下限の中央値と各観測上限の中央値で区間を出す。件数を湯の質の加点にしない。これは全来訪者の比率や将来体感の保証ではない。公式記述と口コミの一致・不一致は併記し、分析値で口コミの体感を上書きしない。

### 4.4 「ほどほどがよい」と指定範囲への適合

全ての数値・件数軸には、同じ生値に対する `target_fit[a,b,d]` という追加系列を定義できる。式はT(a,b,d)に固定する。例えば「施設数5～10程度」「硫黄の量は指定範囲」「1泊料金は予算帯内」を、強い／弱いの符号だけに押し込めず評価する。a,b,dは利用者設定として保存し、未指定の好みを勝手に作らない。利用者が指定する前でも生値を保持するため、再調査せず再計算できる。既定の軸とこの派生軸を重複加算する場合は明示する。

## 5. 採点項目辞書

各行は独立して重みを設定できる。行に「種類ごと」「条件ごと」とあるものはパラメータ化した別IDを生成する。例えばS05[odor=petroleum]、A01[tag=ONSEN_MUSUME]、X01[origin=山形県庁,date=YYYY-MM-DD,route=R001]。既定の重みはすべて0であり、利用者が必要な軸だけ有効にする。

浴槽・源泉単位の行は単に温泉地へ最大値コピーしない。地域への集計は第6節の規則に従う。全項目を確定点だけで埋めるのではなく、公開情報の限界も規定の状態・0点で記録する。

## 6. 温泉地への集計と重み付け

### 6.1 一つの湯と街全体の違い

源泉・浴槽の個別点から地域に持ち上げる際は、次の三つを別列で出す。

1. **選択可能な最高適合**：利用条件を満たす実在浴槽ごとに利用者の重みで計算し、その後で最大を取る。
2. **条件に合う施設の厚み**：その適合を満たす浴槽のある施設数・全施設に対する割合。浴槽を増設しただけで施設数を増やさない。
3. **多様性・希少性・街の特徴**：V/R/H/A/M等の地域単位の軸。最高の一湯と分離する。

個別特性についての地域の「存在」は、具体的な実体が一つでも確認できれば成立する。「不存在」は地域の対象範囲の十分な確認または管理者の網羅的な説明が必要。未調査施設が残る場合、存在数は下限として扱い、上限は既知の全施設数まで広げる。全施設数自体が未確定なら、N(k)の上限は100まで広げる。曖昧な「多数」は件数にしない。

街に硫黄臭の強い浴槽Aと、透明で無臭の浴槽Bがある場合、硫黄臭好きも無臭好きも自分の浴槽を選べる。地域の硫黄臭最大値を先に一つ作ってから符号反転する方法は使わない。「硫黄臭の湯がある街を好む」と「自分が無臭の湯に入れる」は別の評価である。

同じ施設でも「朝は男性・午後は女性」「客室だけ源泉」「冬だけ循環」は利用条件の違う行。同じ訪問で使えない行を合成しない。複数の湯を巡る場合は、その組合せを実際の開館時間、移動、利用条件、費用で成立する湯巡りプランとして示す。

### 6.2 計算式

項目iの重みw_iを−1～1とし、区間に対する保守的適合点a_iを第4.1節で決める。

```text
同一実体・条件の適合点 = Σ(|w_i| × a_i) / Σ|w_i|
```

未知でも分母から外さない。全重み0なら未算出。表示は小数第1位、順位判定には丸め前の値を用いる。同点を勝手に知名度で並べ替えず、同順位にする。表示順が必要なら標準名の読みの順とし、順位差と見せない。

分野間の重みを設定する場合は、各分野内の絶対重み合計を1に正規化して分野点を求め、その後、分野予算g_j≥0で加重平均する。負の好みは末端項目で設定する。項目数の多い分野が自動的に支配しないようにする。有効項目0件なのに正の分野予算が指定されている場合は設定不整合と表示し、他の項目を暗黙に有効化したり分野予算を自動再配分したりしない。

地域の最終評価は、利用者が指定した最高浴槽適合・厚み・多様性・街・アクセス・料金等の重みから作る。浴槽点に既に含めた加工軸を地域評価へ再度足す、A[ALL]とA[ONSEN_MUSUME]を暗黙に二重加点するなどの重複を避ける。重複させたい明示設定は許可し、その設定を保存する。

交通や設備を温泉の湯質点に混ぜない。総合旅先点に含める場合も「湯／街／行きやすさ／費用／設備」の寄与を分解して表示する。数値成分が多いほど自動的に総合点が上がる集計を初期設定にしない。

### 6.3 温泉地・経路・滞在の同時成立

総合旅先点を作るときは、訪問プランを実体にする。

```text
訪問プラン = (実在浴槽, 利用日時, 利用条件, 往復経路, 必要なら宿泊プラン)
```

各プランの湯、移動、利用価格、必要な設備を計算してから最良プランを選ぶ。箱根の入口への最短所要時間と、別地区奥地の浴槽の特徴を無条件で足さない。最安経路の運賃と最速経路の時間を合成しない。高級宿の設備と別の共同浴場の湯を組み合わせるなら、外湯利用と移動を含めた実在プランとして提示する。

重みだけで表せない「日帰り利用必須」「指定温度帯の浴槽必須」などは先に可否のフィルターにする。未確認の必須条件は通過させないが、「利用不可と確認」ではなく「条件充足を未確認」と表示する。

### 6.4 泉質・体験の重複排除

正規化泉質タグはCの10分類を用いる。分析書に「含硫黄－ナトリウム－塩化物温泉」とあれば硫黄・塩化物の2タグを一つの実在供給系統に付ける。単純温泉を独自の一つのカテゴリとして扱うが、古い呼び名や単に温かい普通の水を独断で追加しない。旧泉質名は公開された対照資料で変換する。温度・pH・浸透圧の修飾語を新たな泉質数にしない。

V11の体験プロファイルは、次の有限項目の実在する組で定義する。

```text
(正規化泉質タグ集合,
 P17の状態区分[常時無加工／条件付き／加工確認／未知],
 B03の温度帯,
 S01の自然色,
 S05の自然臭種類,
 B09の独特の形態[該当なしを含む])
```

未知の欄がある二つの行は、相違を確認できる既知項目があるときだけ別種類と数える。同じ源泉・同じ運用・同じプロファイルの浴槽の複製は一種類。季節によって違う場合は季節別プロファイルとして保持するが、同じ時期に両方入れるとしない。

## 7. 47起点のアクセス調査

起点は47都道府県の**都道府県庁本庁舎の一般来庁者用正面入口**。東京都は東京都庁、新宿区の本庁舎の入口とする。各起点の正式名称・住所・座標と根拠を確定して使い回す。県庁所在地であるというだけで任意の駅に置き換えない。利用者が駅等を指定した場合は別設定として保存する。

対象は以下の47件：北海道、青森、岩手、宮城、秋田、山形、福島、茨城、栃木、群馬、埼玉、千葉、東京、神奈川、新潟、富山、石川、福井、山梨、長野、岐阜、静岡、愛知、三重、滋賀、京都、大阪、兵庫、奈良、和歌山、鳥取、島根、岡山、広島、山口、徳島、香川、愛媛、高知、福岡、佐賀、長崎、熊本、大分、宮崎、鹿児島、沖縄。

まず温泉地の公式案内所を地域中心点とする。案内所がなければ公式の中心バス停、さらに無ければ確認した一般利用浴場の中で標準名読みが最初の施設入口を中心点とし、選び方を記録する。広い温泉地は地区中心点も作る。

基準平日・土曜の各9時出発で、公共交通と自動車を分け、47×2×2＝188条件の行を必ず用意する。公共交通では最速・最安・最少乗換の候補を、重複を除いて最大3経路保持する。車では有料道利用可の最速と、有料道を避けた候補を保持する。実際に取得できない条件を概算で埋めず、未調査E・探索済みの取得不能F・公開記述未確認Uを区別して理由を付ける。

公共交通は公式時刻表・運賃、または日時・全行程が確認できる経路検索を根拠にする。タクシー・予約送迎が必要なら明示する。車の燃料費を計算するのは車種・消費率・単価の設定がある場合だけ。未指定なら道路距離と道路料金を分ける。道路工事・冬季閉鎖・運休日を確認する。X05は最終アクセス系統の便数であり、県庁からの全経路候補数ではない。

X06は目的地16～22時出発、X07は起点7時出発・22時帰着という別の明示条件で追加調査する。9時出発の片道行から推測しない。帰路と温泉営業を照合し、現地滞在が0または営業中に利用できない場合を隠さない。

地域中心点への行はアクセス比較の基準行として出力する。実際の浴槽を使う総合評価では、その浴槽までのラスト区間も結合した別経路を使う。価格・時間・乗換は同一経路の組で採点する。経路選択は利用者の重みを当てた後に行い、常に最速経路だけが正解としない。

## 8. 調査の進め方と終了条件

### 8.1 調査順序

1. 名称・実在・境界・公式の施設一覧を確定する。地域総量と各施設のデータを分ける。
2. 一覧の各施設について、源泉・浴槽・分析書・利用方法掲示・FAQ・利用条件・料金・休業情報を確認する。日帰り／宿泊／住民限定を分ける。
3. 泉質・加工・温度・体験が異なる浴槽を各施設内で分ける。代表浴槽一つの値を全施設へ配らない。
4. 各源泉・混合系統の分析書を開き、源泉名、採水日、単位、ガスを除く溶存物質、pH、泉温、成分、分類を転記し、供給対応を確認する。
5. 口コミを所定の選定規則で取得し、体感の根拠と採点を作る。
6. 地域文化・施設・活動を調べる。温泉むすめは権利元、地域運営者、設置・販売・主催の各当事者を調べる。
7. 起点別アクセス・料金・営業・利用条件を別表にする。
8. 全項目の欠測、条件、矛盾、集計、計算を検算して出力する。

### 8.2 Uと判定する前の必須探索

源泉・加工情報では、施設の温泉ページ、FAQ、利用案内、分析書・掲示写真・PDF、供給元／自治体／地域公式資料を確認し、さらに「施設名＋温泉分析書」「施設名＋加水 加温 循環 消毒」のように項目別検索をする。リンク先が判読できない・開けない場合は、原URLの再取得、公式サイト内での資料名検索、同じ発行主体の代替掲載先の探索を行う。それでも取得できない場合はF、これらの探索自体が未実施ならEとする。別の有効な資料で項目を確認できた場合、失敗したリンクは取得ログに残し、採点行はその有効な根拠の状態にする。確認した資料に書かれていないことを、世界中に未開示である証明と誤記しない。Uの表示は「この調査範囲で公開情報を確認できず」。

活動では、古い専用サイトに止まらず、地域公式の新着情報、運営主体、参加施設、権利元の該当温泉地記事を検索する。過去のパネル一覧や終了済みイベントだけで、現在活動している／していないと断定しない。

### 8.3 調査完了の条件

- 各対象施設について調査実施状況が台帳化され、必須探索を実施したか追跡できる。
- 全250基本項目と必要なパラメータ展開について、K/C/Z/U/X/F/Aのいずれかを記録する。Eが残る部分は未調査残として明示し、その部分を完成と称さない。
- 箱根や別府で施設数が多い場合は地区別ファイルに分割する。代表例数軒の調査を全件調査と呼ばない。媒体の出力量の都合で対象施設を黙って切り捨てない。
- 全施設の確定した分母がない割合は区間扱い。件数の下限しか把握していない場合は下限と記す。
- 188アクセス条件の存在確認、取得済み数、未取得数を示す。47件を距離の近さから推測して埋めない。
- 他温泉地との比較台帳がなければ、希少性の点を作らず「母集団未接続」とする。対象温泉地の調査失敗と混同しない。

完了とはすべてが100点または確定値になったことではなく、**何が確認でき、何が未開示で、どの値がどの条件に適用されるかを、全項目について判定し終えたこと**である。

## 9. 出力形式

必ず以下の順で出力する。調査データが長い場合は、本文に要約、添付ファイルに全台帳を出す。ファイルを作れない環境では地区・表ごとに分け、未出力の範囲を明示する。未出力データが存在するかのようなリンクを作らない。

### 9.1 対象定義と結果の概要

標準名、別名、評価日、範囲、構成地区、確認施設数、対象モード、調査完了状況を示す。好みとの関係が明確な特徴を具体的根拠とともに短くまとめる。総合的な有名・おすすめの形容で個別採点を代替しない。

### 9.2 源泉・供給・浴槽一覧

```text
地域ID | 地区ID | 施設ID | 浴槽ID | 源泉/混合系統ID | 分析試料ID |
日帰り/宿泊条件 | 季節・時間条件 | 泉質タグ | 湯温 | 主要加工 | 根拠ID
```

浴槽が特定できない施設説明はfacility_scopeにとどめ、その不明点を表示する。単一源泉でも複数の運用条件があれば分ける。

### 9.3 全項目採点表

```text
項目ID[パラメータ] | 対象実体ID | 利用・季節条件 | 生値 | 単位 |
状態 | 素点下限 | 素点上限 | 表示点 | 採点式・代入値 |
根拠ID | 説明・未確認理由
```

地域に対しては、各特性の「存在」「確認できた施設数」「全体に対する割合または区間」を必要に応じて別系列で添える。各系列の意味を列名に入れる。出典のない確定点を作らない。

### 9.4 アクセス・料金・活動の別表

47起点の平日・土曜、公共交通・車の188条件を示す。複数経路は経路IDで区別する。料金は日帰り／宿泊／貸切で条件を固定する。活動は実施済み・現在利用可能・将来予定・終了を分ける。

### 9.5 主要な情報差と条件分岐

順位や利用判断を変える条件を具体的に示す。「この浴槽だけ」「冬季のみ」「日帰り客不可」「本文と分析書の混合源泉違い」など。単なる一般的な注意事項ではなく、採点根拠の適用に必要な差に限定する。

### 9.6 好みを指定した場合の寄与表

利用者の重みがある場合だけ、適合点、最も適合する実在浴槽または訪問プラン、各項目の加重寄与、条件適合施設数、確認度を出す。

確認度は、有効な重みの絶対値で重み付けした「点または拘束された区間を持つ項目の割合」と、区間幅から得る「数値確定度」の二つを出す。

```text
根拠取得率 = 100×Σ(|w_i|×e_i)/Σ|w_i|   # K/C/Zで対象との対応ありならe_i=1、その他0
数値確定度 = 100×Σ(|w_i|×(1−(U_i−L_i)/100))/Σ|w_i|
```

A/E/U/Fの数値確定度は0とする。Xで拘束された区間がある場合は区間幅を用い、矛盾ありを表示する。確認度を湯の魅力へ自動乗算して二重に減点しない。すでに欠測は寄与点0として扱っている。

### 9.7 検算結果・調査残・根拠一覧

第10節のチェックを実行し、失敗した規則IDと修正内容を示す。未調査の施設、取得失敗の資料、未接続の比較台帳をそれぞれ区別する。根拠はURL・主体・対象・日付・引用位置を含める。

機械可読出力が可能なら、全採点表を同じフィールド名のJSONにする。事実のnullと採点0を分ける。架空の値を入れた見本JSONを実データの出力に混ぜない。

## 10. 提出前の必須検品

1. 全ての確定点に、生値または成立条件・式・根拠・適用対象があるか。
2. 源泉の値と浴槽の値、現地pHと室内pH、混合前と混合後を混ぜていないか。
3. 分析書と本文で源泉名・構成井戸・採水点・日付が食い違っていないか。
4. 加水・加温・循環・消毒・添加の未記載を「なし」にしていないか。
5. 掛け流しの語だけから無加水・無加温・無消毒を導いていないか。
6. 未知0点・区間値が負の重みで有利になっていないか。
7. 体積割合、時間割合、施設割合を取り違えていないか。
8. 五条件同時無加工を別浴槽・別時期の最大値や独立積で作っていないか。
9. 口コミの無言を否定にせず、単なる存在記述を強度の確定点にしていないか。
10. 泉質数、源泉数、地区数、色数、実在する組合せ数を混同していないか。
11. 大規模温泉地の総湧出量を浴槽鮮度として使っていないか。
12. 見学地獄や閉業施設を利用可能浴槽に数えていないか。
13. 日帰り客の時間に宿泊者の24時間利用を流用していないか。
14. 設置物の移設前後、同一地点の複数絵柄、同一企画の複数告知を二重計数していないか。
15. 昔の活動実績だけで現在の活動を判定していないか。予定を実施済みにしていないか。
16. 対象温泉街の外の便利さ・店・設備を勝手に取り込んでいないか。
17. 最速時間と最安運賃など、実在しない経路・訪問プランを合成していないか。
18. 選ばれた浴槽・客室・経路の料金、日時、利用条件が同時成立するか。
19. 未調査を未開示、未開示を実在しないという意味に書き換えていないか。
20. 同じ根拠を二回与えても点が変わらず、重み0の項目や無関係な温泉地を追加しても既存点が変わらないか。

## 11. 拡張の規則

新しい特徴が見つかった場合、まず既存のパラメータ行に入るか確認する。入らない場合は、名称・対象実体・生値・単位・根拠要件・0～100の固定尺度・未知時・季節時・負重み時・地域集計時の挙動を定義し、仕様版を更新して初期重み0で追加する。旧版で取得した生値は保持する。

「唯一」「高級」「秘湯」「良質」「活性化に成功」等の総合語を新しい自由裁量点として追加しない。その語が利用者にとって何を意味するかを、検証可能な末端項目に分ける。

## 12. 分類・分析の公開参照先

実行時点で有効な公開資料を確認する。次は設計時に確認した参照先であり、そのまま最新性を保証するものではない。

- 環境省・温泉関連資料一覧：https://www.env.go.jp/nature/onsen/docs/index.html
- 環境省・鉱泉分析法指針（平成26年改訂）：https://www.env.go.jp/nature/onsen/pdf/2-5_p_14.pdf
- 同指針の分類、化学種・単位、源泉と採水点、知覚試験を参照する。指針の成分閾値と、本仕様独自の採点目盛りを区別する。
